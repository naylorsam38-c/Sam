Aura — Unified Specification

Self-hosted, live, interruptible interactive avatar runtime that presents an external brain. One document merging the v1.0 architecture spec and the full implementation spec, reverse-analysed and improved.

Version 2.0 (merged + improved)Supersedes: v1.0 spec + implementation specStatus: build-readyOwner: Aura / Command Desk
What this is. Aura gives an existing brain (Command Desk) a face and a voice. A user speaks or types; Aura listens, transcribes, asks Command Desk what to say, and streams a lip-synced, emotionally-expressive talking avatar back over WebRTC with audio and video tightly synchronised — fully interruptible. Every model runs on infrastructure you control; no paid external AI/avatar/speech/video/per-minute services are required. Aura is a presentation service, never the brain.

1Purpose & scope

In scope

A deterministic, interruptible, low-latency presentation runtime: microphone/text in → secure WebRTC session → VAD → local STT → Command Desk → streamed response text → local TTS → live facial animation + lip sync → synchronised WebRTC audio+video → app display. It exposes a clean internal API, a set of deterministic session states, and a bidirectional data channel for state/transcript/timing/errors.

Out of scope (explicitly)

The brain itself. Reasoning, agents, memory, oversight and the response policy live in Command Desk and are reached over an internal endpoint. Aura never rebuilds, replaces, relicenses, or silently changes Command Desk. Aura only transports text in and streamed text out, and turns replies into audio+video.

2Reverse-analysis: what changed and improved

Merging the two specs surfaced gaps and ambiguities. These are the deliberate improvements folded into v2.0:

Licensing corrected & machine-enforced. MuseTalk is not OpenRAIL-M: code = MIT, trained model = commercial-use allowed, bundled deps audited separately, supplied test data non-commercial (never shipped). Added a dependency-lock manifest + a build-failing audit gate (§19) with hard fail conditions; "licensing verified" is now a checked machine state, not a claim.
Audio is the master clock, made concrete. Every video frame's PTS is derived from an audio timestamp; a DriftMeter measures real A/V drift continuously against an 80 ms budget (§7). Lip motion is never animated on an independent clock.
State machine transitions defined. The source spec named states but not legal transitions; v2.0 specifies the transition table and illegal-transition handling (§5).
Echo cancellation + double-talk disambiguated. Split into client-side WebRTC AEC (capture) and server-side double-talk detection that drives barge-in (§7–§8) — the source spec listed "echo cancellation" without an owner.
Region-ownership compositor formalised. Exactly one controller writes each facial region; a compositor blends with masks + temporal smoothing + identity lock + transition blending to stop teeth/eye shimmer (§9).
Enhancement policy hardened. Enhance the source once; targeted masked touch-up only; never per-frame; CodeFormer banned (non-commercial); GFPGAN default (§9, §19).
Quality ladder given hysteresis. Cooldown prevents oscillation; explicit down/up triggers; the CPU fallback is a permanent Level 0 so the face never freezes while the session lives (§10).
Codec default changed to VP8/VP9. Royalty-free, avoiding H.264/MPEG-LA patent exposure; H.264 opt-in only (§14, §19).
Detector swap mandated. LivePortrait's InsightFace models are non-commercial → replaced by OpenCV YuNet for detection/landmarks (§9, §19).
SLOs, not just an average. p50/p95 latency targets, drift budget, cold-start budget, and a load-test gate before raising the user cap (§16, §20).
Privacy/biometrics governance. Face+voice are biometric identifiers; consent + retention/deletion policy + no runtime dynamic weight downloads are explicit (§15, §18, §19).
Perceptual QA harness for Phase 1. Automated identity-region SSIM + mouth-region variance checks flag teeth flicker / identity drift, backing the human review gate (§9, §20).
Reconnect/resume protocol + repeated-interruption stability added to failure handling (§17).

7Real-time pipeline & timing

Phrase streaming

Do not wait for the full answer. A phrase chunker detects natural boundaries and emits ~4–12 words at a time into TTS, keeping a small audio buffer so speech stays continuous.

Audio is the master clock IMPROVEMENT

Every generated video frame corresponds to a defined audio timestamp; frame PTS = audio PTS. Lip movement is never animated independently from sound. A DriftMeter samples (video_pts − audio_pts) continuously; target drift < 80 ms, measured and reported (a drift event fires when exceeded).

Echo & double-talk IMPROVEMENT

Client-side WebRTC AEC (browser echoCancellation`, native AEC) removes the avatar's own audio from the mic. Server-side double-talk detection lets VAD fire during playback so the user can interrupt (barge-in) even while the avatar speaks.

8Barge-in & cancellation

True user interruption. When the avatar is speaking (and the turn is interruptible) and the user starts talking:

  1. detect the user immediately (VAD during playback);
  2. stop current TTS generation;
  3. discard unplayed audio;
  4. cancel queued speaking frames;
  5. return the avatar to attentive listening;
  6. transcribe the new speech;
  7. notify Command Desk that the previous response was interrupted (with the interrupted turn_id).

State path: SPEAKING → INTERRUPTED → RECOVERING → LISTENING. Cancellation is cooperative: each worker exposes cancel_current() and its queue is drained. Repeated interruptions must never wedge the session (§17).

Region ownership & conflict prevention IMPROVEMENT

Exactly one controller writes each region: jaw/mouth → lip-sync; eyes/eyelids/eyebrows → expression; head pose → motion; shoulders/breathing → idle layer; background → fixed unless animated. A compositor blends per-region layers with masks, landmark stabilisation, temporal smoothing, identity locking, and transition blending so two models never fight over the same pixels.

Enhancement policy IMPROVEMENT

Restore the source portrait once (identity-preserving), cache it. At runtime apply only targeted masked restoration where a check flags softness — never the whole face, never every frame — to prevent teeth/eye shimmer and identity drift. CodeFormer is banned (non-commercial); GFPGAN is default.

Fallback animations (must all exist)

neutral idle · breathing · blink · attentive listening · thinking · faint smile · transition into speech · transition out of speech · renderer-failure loop. The CPU fallback renderer provides these with no GPU so the avatar is alive in every state.

Reduce visual quality before sacrificing speech, timing, stability, or the session. Down-shift on drift-over-budget, dropped frames, render latency > frame budget, or GPU mem > 92%; up-shift only when relaxed, after a cooldown (hysteresis prevents oscillation).

11Liveliness requirements

The avatar must blink, breathe subtly, maintain natural eye contact, make restrained head movements, occasionally smile, and move its mouth clearly while speaking. It must remain visually alive while idle, listening, thinking, speaking, interrupted, or recovering. It must never become a frozen photograph unless the complete renderer has failed (and even then the fallback idle loop runs).

12Concurrency & workers

Seven independently-managed workers, even on one machine: session gateway · audio/VAD · STT · Command Desk connector · TTS · avatar renderer · WebRTC publisher. Each has: bounded queues; health checks; timeouts; cancellation; backpressure; structured logs; restart behaviour; metrics.

Backpressure policy per queue: render/publish = drop-oldest (freshest frame wins); brain/TTS = bounded block (never lose words). Every drop is counted.

Do not assume all models run in one uncontrolled GPU process: explicit GPU-memory budgets, model warm-up, worker scheduling, and a config option to move LLM/render/speech to separate GPUs later (§13–§14).

15Security & privacy

  • Short-lived signed session tokens; scoped to one room + one user.
  • No exposed model/render/Command-Desk ports; gateway + LiveKit media only, behind TLS; media is DTLS-SRTP.
  • Per-user session isolation — a user cannot enter another user's room; one active session per user; rate limiting.
  • Upload validation + image size/dimension limits; temp-file cleanup; audio/frame deletion policy (not persisted beyond the turn).
  • AuthN/AuthZ via your IdP; audit logs for session issue/verify/interrupt.
  • IMPROVEMENT Biometrics/privacy: face + voice are biometric identifiers — record consent (§18), honour retention/deletion, and comply with local biometric-data law. No dynamic weight downloads at runtime (ties to §19).

16Observability & SLOs

Per-turn metrics: VAD start/end · STT start/final · Command Desk request · first token · first TTS audio · first rendered frame · first published frame · total latency · dropped frames · queue depth · GPU util · GPU mem · A/V drift · interruption count · reconnect count · error source. Health checks per worker; structured JSON logs; correlate by turn_id.

SLOs (not just an average): response latency p50 <1.0 s, p95 <1.6 s; A/V drift p95 <80 ms; dropped-frame rate <1%; cold-start <10 s; uptime target per your ops. A load-test gate must pass before raising the user cap.

18Avatar source & consent

Source portrait must be: front-facing or nearly so; eyes fully visible; mouth visible and preferably closed; even lighting; sufficient resolution; no obstruction over mouth/jaw; shoulders included when breathing is required; background separated or fixed; identity ownership and consent recorded. Preprocessing: validate (with a commercially-licensed detector — YuNet, never InsightFace) → enhance once → detect anchors → background lock → emit manifest. Nova/Halo/Gaia and any future asset each get a validated bundle + consent record.

19Licensing governance IMPROVEMENT

Open source is not automatically free for commercial use. Two artefacts enforce this:

  • Licence register — human-readable classification of every component (clear / conditional / blocked).
  • Dependency lock + audit gate — a manifest with exact repo URL, commit hash, package version, weight filename, SHA-256, code licence and weight licence for every component; a script that fails the build.

Corrected commercial-safe route: Lip sync = MuseTalk (code MIT; model commercial-use-allowed; audit + pin every bundled dep & weight; do not ship its test data — non-commercial). TTS = Kokoro. Motion = LivePortrait only after fully removing InsightFace pretrained models and replacing its detection/landmark dependency with a commercially-permitted one. Restoration = not CodeFormer. Voice cloning = not XTTS-v2. Fallback lip sync = not Wav2Lip.

The build FAILS if: a dependency has no licence · code and model-weight licences differ and either is unapproved · a model downloads weights dynamically from an unverified source · test assets/datasets are non-commercial · InsightFace weights appear anywhere · CodeFormer, XTTS-v2 or Wav2Lip appear transitively. Do not label the repo "licensing verified" until the complete transitive tree, weights, voices, datasets and test assets pass. Codec default VP8/VP9 to avoid H.264 patent exposure.

20Build phases & gates

  1. Offline visual proof — prerecorded speech → stable talking avatar ≥2 min. Pass only when: identity recognisable; eyes/hair/jaw/outline stable; teeth don't flicker; lips match; no progressive drift; smooth transitions. IMPROVEMENT backed by an automated identity-SSIM + mouth-variance harness plus human review.
  2. Streaming text-to-avatar — speak/animate before the full response arrives (4–12-word chunks).
  3. Command Desk connection — stream real responses through unchanged; interrupt-notify.
  4. Live microphone — VAD, STT, echo cancellation, interruption, cancellation, recovery.
  5. WebRTC clients — browser + Flutter reference, then iOS/Android guidance.
  6. Hardening — auth, monitoring, quality scaling, worker recovery, security, licensing records, deployment, tests, docs.

Support one reliable user before multi-user scaling. Release gate = tests pass + phase gates pass + licence audit = PASS + load-test SLOs met.

21Definition of Done

All nine states with enforced transitions; barge-in works end to end; phrase streaming 4–12 words; audio-mastered timing with measured drift <80 ms; workers have queues/health/timeouts/cancellation/backpressure/logs/restart/metrics; quality ladder + all fallback animations; thin clients for browser/Flutter/iOS/Android; full security controls; complete metrics; failure handling for every §17 case; licence register + dependency lock + audit gate returning PASS; runs with no external per-use paid services; one reliable user proven. A genuinely interactive, interruptible, synchronised, self-hosted avatar runtime you own, wired to Command Desk, usable later with Nova, Halo, Gaia or other approved assets.

22Non-goals & prohibitions

  • Do not rebuild or replace Command Desk (brain, agents, memory, oversight).
  • Do not use paid hosted AI/avatar/speech/video/per-minute APIs.
  • Do not hardcode around one avatar, one model, or one client.
  • Do not pass off a visual mock-up or prerecorded video as the live system.
  • Do not silently change the existing backend.
  • Do not claim zero cost (§24) or "licensing verified" before the audit passes.
