# Findings — shelf lifecycle added, first full loop run on Command Desk (2026-09-05)

Everything below was produced by running code, not by reading it. The loop
(`packages/loop/run_chain.py`) ran end to end on the real Command Desk spec
for the first time; the seam journeys drove real Chromium against the real
built app; the shelf's lifecycle was initialised and four parts earned
receipts. Whole repo: **209 tests passing** (was 186).

## What was added (the four things Sam approved; nothing else restructured)

1. **Part lifecycle + pinned revision** — `packages/builder/shelf.py`. Every
   part carries `version`, `status`, `qualified_revision`, `provenance`,
   `seam_journeys`. Status is earned by receipts from the live tester, never
   typed. `freeze` is one-time; `bump` is the only way to change frozen bytes.
   `shelf.py check` reports any qualified/frozen part whose bytes moved.
2. **Pins in every bound spec + app manifest** — `bind_and_assemble.py`
   writes `part_bindings.pins` (part@version, source revision, status);
   `check_capability_bindings.py` gained a QUALIFICATION section (DRIFT /
   UNQUALIFIED per part, `--require-qualified` to fail on it); the Builder
   writes `MANIFEST.json` into every built app (parts *used* vs *vendored*).
3. **Seam journeys owned by parts** — `packages/playwright-tester/seams.py`,
   7 journeys, mirrored on each part's `seam_journeys`. Run by the loop after
   the normal tester. PASS (browser-verified, re-read) is the only result
   that qualifies; BLOCKED / FAIL / N/A are all printed.
4. **Provenance + licence** on all 33 parts (`read_from` reference apps,
   original implementation, owner's all-rights-reserved default).

Definition of Done now also asks the shelf: every part the app uses must be
PRODUCT_QUALIFIED at the exact revision the app vendored.

## Loop result on Command Desk: NOT DONE, 19 defects — every one real

Two are product defects the seam journeys caught:

- **SCR-017 "Upload a document"** — the browser cannot submit the form. The
  generated submit script JSON-encodes the `File` object as `{}` and the
  server dies binding a dict into sqlite ("Error binding parameter 2"). No
  file-carrying submit path exists in `form_render_submit`; the natural home
  for the bytes is the shelf's own `preserved_original_document_store`. This
  is a product decision (what an upload stores) — not guessed.
- **ACT-024 "Open source document"** — was proposed (PROPOSED_ANSWERS) as
  `clear_fields []`, which reached sqlite as `UPDATE … SET  WHERE …` and
  returned 500. `custom_action_execution` now refuses an effect that changes
  nothing (400 with the reason; regression test added). The action still has
  no working implementation: it needs a real effect, or removing.

Eleven are one UI gap, reported per numbered item: **the generated screens
carry no lifecycle stage and no action controls.** Detail screens render the
record's fields only, so every move (person-moved, system-moved, approved)
happens over the API and no screen shows it; Pause, Retry and the
person-moved transitions have no button a user can press; the approver has no
control. `report SCR-018` is the same gap from the other side (its metrics
count jobs at done/failed, unreachable from any screen). These are Builder
work — `_render_detail_screen` needs the stage and the declared actions.

Six are the shelf gate: `form_render_submit`, `workflow_executor`,
`system_triggered_transition`, `stage_approval_gate`,
`custom_action_execution`, `audit_trail` are used by the app but only TESTED.
They cannot qualify until the UI gap above is closed (their journeys are all
BLOCKED on it). `audit_trail` additionally has no route or screen that exposes
the trail, so no journey can ever verify it until one exists.

Two notes (not defects, recorded on the journeys): on a fresh install the
"Add an agent" and "Upload a document" forms cannot be completed from the
screen because their required links (Reports to → Agent, Job → Job) have
nothing to pick.
