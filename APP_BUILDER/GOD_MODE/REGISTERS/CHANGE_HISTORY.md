## Harvest Admission Rule merged and activated

The proposed harvest admission rule was replaced by a single complete rule at
`GOD_MODE/ACTIVE/GOD_MODE_RULE_HARVEST_ADMISSION.md`. Changes from the proposal:

- Rule A widened from framework to **stack** — Flask *and* PostgreSQL, one stack
  across the whole library, because parts are only interchangeable if they speak
  the same language underneath.
- Rule E added — one source repo per app.
- Rule F added — where no repo on the stack provides a capability, the
  capability is written directly against the stack. A written part is a
  first-class shelf part; it names this system as its origin instead of an
  upstream commit. This is what makes Rule A affordable.
- The payload question is settled: a harvested part runs as its source wrote it.
  The host does not need to stay framework-neutral because, under Rule A, there
  is no second framework to stay neutral between.
- Scope corrected: the `gen_common.py`-generated capabilities are **not**
  grandfathered. Their implementation records carry `"commit": "gen_common.py"`
  rather than a real upstream commit; they fail Rule A on provenance and are out
  of scope as stock.
- Enforcement table now states which rules the form gate cannot yet check,
  rather than implying full coverage.

Recorded as open: `_extract_route_meta` reads `ROUTE`/`METHOD` literals while
Flask declares routes by decorator.

## 2026-09-15 — Whole-module harvest, and the host that serves the shelf

**Harvest no longer cuts line ranges.** The harvester fetches the whole module
a symbol lives in. The recorded line range stays on the provenance as the
symbol's address but no longer limits what is fetched. Settings
`HARVEST_WHOLE_MODULE` and `WHOLE_MODULE_MAX_LINES` in `harvest_parts.py`.

Cut fragments did not run. An AST check on the fragment shelf returned zero
imports on every part, 28 unresolved names on one, and one part that would not
parse at all. The same check on whole modules: all ten parse, imports present,
zero unresolved names.

**The host exists.** `host.py` builds the source application's own stack, then
serves only the routes belonging to capabilities on the shelf. Everything else
the source ships is refused at dispatch. The shelf decides what the app is.

Proven over a real socket against real PostgreSQL 16.15 and real Redis, with
Indico 3.3.13 installed from a real wheel: ten capabilities answered, 1120
routes refused, zero failures. Responses served by a shelf capability carry an
`X-Shelf-Capability` header naming the number that served them.

**Correction recorded.** The check-in route was reported missing and was not.
It is `/api/checkin/event/<int:event_id>/` with a trailing slash; the check
compared the string without one. Eight real check-in routes are live. The fault
was in the comparison, not the code.

**Open item closed.** `_extract_route_meta` reading `ROUTE`/`METHOD` literals
while Flask declares routes by decorator is handled by `route_reader.py`,
patched into `build.py`.

## 2026-09-15 — `watch.py` specified

The last of the three unresolved items is closed. Sam's direction: it audits the
whole loop, and it aligns with god mode.

**Written fresh, not recovered.** Bible Part Eight was never supplied and is not
on this machine. Every check in the new spec traces to something already locked —
the Script Standard's hard rules, environment hygiene and output contract, or the
Build Chain Standard's own account of what each layer may and may not do. Nothing
was invented to fill the gap, and the spec claims no lineage to the missing
document.

**Twenty-two checks in three groups.** Did the run really run (fresh working
directory, real process on its own port, real datastores, nothing mocked). Was it
actually proved (a level-1 journey in a real browser, that passed, with no
javascript errors, every claimed check with a verdict against it, output contract
held). Did the loop behave (repairs came from the shelf and restarted as new runs;
if a model was called, the gap record existed first and was complete, the model
got the record and nothing else, several candidates were generated, the winner was
driven through the full chain, touched only the part, and was held for approval
rather than shelved automatically; no gap raised twice; no regression; every part's
origin recorded as harvested or written).

**Read-only by design.** It never repairs, never writes to the shelf, never calls
a model, never touches the app. A script that could fix what it audits would have
a reason to go easy on it.

**It distinguishes "did not happen" from "happened correctly."** A run that never
entered layer three reports those checks as SKIP and still passes, because not
needing a model is not a failure. A run that skipped its browser check does not.

**Exit 2 when it cannot audit.** Missing or unreadable records claim nothing, the
same way a script that cannot start claims no checks. A run that cannot be audited
is not BUILT.

**What has not happened.** The script has not been built. The spec exists; the
file does not. A chain reaching BUILT today has passed layer one and a level-1
journey and has still not been audited. That remains true until `watch.py` is
written and has been seen to fail — five break tests are named in the spec.

## 2026-09-15 — `watch.py` built, and the run-record contract with it

The spec written earlier today is now a script. Before it could be, something
had to exist for it to read: no part of the chain wrote a record a run could be
audited from. `run_record.py` is that contract — one record per run, written on

Audited against real runs of the real host: real PostgreSQL, real Redis, real
chromium, part origins read off each part's own provenance file. Seven breaks
run for real, each one restored afterwards. The one that matters: with the
database left over from the previous run, `host_test.py` reported PASS and
exited 0, and `watch.py` refused it on `W-01`.

**Unproven and named as such:** `W-13` to `W-19` audit layer three, which no run
has entered because `layer3_gap.py` does not exist. No gap was fabricated to

## 2026-09-15 — pressure test: a repair has nowhere to land

Every script driven against adversarial input. All four obey their stated exit
codes exactly and none claims anything on a run it could not complete.

**The blocking finding.** `CAP-0002`'s `source.py` was emptied on the shelf and
all eleven checks still passed. `host.py` reads that file only to decide which
capabilities exist; the code that runs is the source application's own, resolved
from its live URL map. The shelf governs which routes are served, not what they
do. There is therefore no location where a repair or a built part changes the
app's behaviour. This blocks layers two and three and is the thing to solve
before a model key is worth buying.

Neither layer fails silently, and that was verified. Layer three applies each
candidate and judges it against the real system, so an inert candidate fails and
is discarded. Layer two applies and restarts, and the loop guard names it.

**Four defects found and fixed.** Layer two was writing repairs into a directory
the app never reads. Layer three was judging candidates it had never applied.
Layer three refused to retry a gap whose previous attempt built nothing, making
it permanently unfixable. No check recorded which capability it drove, so layer
three would have refused every failure the day a key arrived — the test knew all
along and now writes it down, through `run_record.check(capability=...)`.

Chain re-proved clean end to end: RUN-0029 BUILT, exit 0.

## 2026-09-15 — the shelf runs the app, and no app governs the system

The shelf's own copy of each part is now the code that serves its route. The
host builds the runtime a part needs, then binds the shelf part over it. Each
part names its entry symbol in its own `PROVENANCE.json`; compound and dotted
symbol names are read as written, never guessed at.

No application is named anywhere in `host.py`. The runtime factory, model loader
and view adapter moved into the app's own form under `harvest_source`, because
they are facts about that app. A source repository's name survives only in each
part's provenance, where licensing requires it, and nothing reads it to decide
behaviour.

`host_test.py` binds identically, and records one check per capability proving
it is served by its own part.

Proved: `CAP-0002` emptied on the shelf -> log in failed, layer two found no
part, layer three held naming `LAYER3_ENDPOINT` (RUN-0035). Restored ->
RUN-0036 BUILT. This is what gives a repair somewhere to land.
