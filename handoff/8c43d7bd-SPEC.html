Aura — Technical Specification

A self-contained, commercial-grade, real-time interactive talking avatar that runs entirely on hardware you own and wires into any app.

Version 1.0Status: proposedOwner: Aura projectType: engineering spec
Objective. Build one backend service that takes a single still image and turns it into a live avatar which listens (voice), reads (text), thinks, speaks, and appears as a photoreal talking face — streamed to any client. No third-party avatar/AI SaaS in the loop and no per-use billing: every model is open-source and self-hosted. The one hardware requirement is a GPU, because real-time face rendering is compute-bound. "Commercial grade" is defined by the measurable acceptance targets in §7.

1Scope & principles

  • Self-contained. All inference (speech-to-text, language model, text-to-speech, face rendering) runs on your own GPU server. Unplug the public internet and it still works.
  • Backend does everything. The server runs the full loop and emits finished video+audio. Clients are thin: they capture mic/text and play a video stream. Nothing heavy runs on the device.
  • Wire into anything. The avatar is exposed as a WebRTC stream + a text channel, so web, iOS, Android, Flutter, or desktop all connect the same way — one integration, every platform.
  • Dual input. The user can speak or type; both feed the same brain. Output is always the talking face.
  • No money model. Open weights only; cost is hardware + electricity, not licensing or per-minute fees.

4"Getting the video right" — the hard 80%

Commercial-grade video is six requirements met at once. Each maps to a specific technique with an acceptance criterion.

RequirementHow it's achievedAcceptance criterion
Accurate lip-syncMuseTalk — phoneme-aware latent-space inpainting of the mouth region driven by the TTS audioCorrect visemes; reads as speech, not flapping
Temporal stabilityMuseTalk conditions each frame on the original face as reference; add frame-to-frame latent smoothingNo flicker/jitter over a 2-min take
SharpnessRender at model resolution, then GFPGAN/CodeFormer face restoration + upscaleClean 720p+; no soft/blurry mouth
Life (motion)LivePortrait / idle-motion driver layered under lip-sync: head sway, blinks, micro-expressionsNever a frozen mask; natural idle
Audio-visual syncTimestamp TTS audio chunks; buffer frames to lock lips to soundLip offset <80ms (imperceptible)
Speed (real-time)GPU batching + ONNX/TensorRT optimization; start rendering as first audio chunk arrivesSustained 25–30 fps on one GPU
Honest note: hitting all six simultaneously and smoothly is the engineering effort. Every part is a known, open model — the work is integration and tuning, not invention. The residual quality gap versus the very best hosted APIs is closed mostly by the enhancement pass (§4, row 3) and a clean, front-facing source image.

5Turn sequence (render loop)

  1. Client sends mic audio (or a text message) over WebRTC.
  2. VAD marks end-of-speech → Whisper finalizes the transcript (text input skips this).
  3. Transcript → Llama; tokens stream out as they generate.
  4. Completed sentences stream to TTS → audio chunks produced continuously.
  5. Each audio chunk drives MuseTalk → face frames; enhancement + motion applied.
  6. Compositor syncs frames to audio, muxes, pushes to the outbound video track.
  7. Barge-in: if the user speaks, the current generation is cancelled and the loop restarts.

6Interfaces (how any app connects)

  • Join: client requests a token from a tiny auth endpoint, then connects to the LiveKit room.
  • Up: microphone track (voice) and/or a text message on the data channel.
  • Down: one video track (the talking face) + its audio.
  • SDKs: LiveKit ships Web/React, Swift (iOS), Kotlin (Android), Flutter, React-Native — the same backend serves all of them.

8Build plan — how it gets achieved

Phase 0 Environment

Provision a GPU host (start: RTX 3060-class 8GB; smooth real-time: RTX 4090 / A10). Install CUDA, pull all model weights, smoke-test each model standalone. Exit: every model runs on the box.

Phase 1 Video quality (offline)

Build text → TTS → MuseTalk → enhance → mp4. Tune until §4's six criteria pass on a fixed sentence. Exit: a clip that looks commercial-grade.

Phase 2 Full loop (offline)

Add Whisper + Llama for a complete listen→think→speak→render turn, file-based. Exit: type/speak in, correct talking reply out.

Phase 3 Real-time streaming

Wrap the pipeline in LiveKit; stream frames live; overlap stages; optimize (TensorRT/batching) to hit the latency + fps targets. Exit: sub-1s live conversation.

Phase 4 Polish

Barge-in/interruption, idle motion, enhancement tuning, A/V sync lock, 2-minute stability. Exit: all §7 targets met.

Phase 5 Integration

Token/auth endpoint, client SDK samples (web + mobile), text channel, deploy as a service. Exit: embedded and running in a real app.

10Dependencies

Hardware: one CUDA GPU. Software (all open-source, self-hosted): LiveKit, faster-whisper, Silero VAD, Llama 3.x + vLLM, XTTS/Kokoro/Piper, MuseTalk, GFPGAN/CodeFormer, LivePortrait, PyAV/ffmpeg. No external accounts, no SaaS, no per-use billing.
